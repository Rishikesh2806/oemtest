<analysis>**original_problem_statement:** The user wants to build a full-stack web application called **OEMLinker**, an AI-driven on-demand manufacturing marketplace. The core functionality involves buyers uploading RFQs with engineering drawings. An AI engine analyzes these drawings to extract technical specifications, which a smart matching algorithm uses to connect buyers with suitable manufacturing vendors based on capabilities, dimensions, and location.

The platform must support a complete workflow: RFQ -> AI Analysis -> Vendor Matching -> Quotation -> Purchase Order -> Delivery -> Payment. It should handle different user roles (Buyer, Vendor, Admin) and include features like a vendor capability database, dashboards for each role, and a secure escrow payment system.

**PRODUCT REQUIREMENTS:**
-   **User Roles:** Buyer, Vendor, Admin, and custom staff roles (e.g., Sales Manager), all managed via a full RBAC system.
-   **AI Core:** An Intelligence Engine to read drawings and an AI assistant for user interaction.
-   **Matching:** A smart algorithm to match RFQs to vendors.
-   **Workflow:** A complete RFQ-to-payment lifecycle management module.
-   **Security:** Secure user authentication and granular, role-based permissions.
-   **Commercials:** Escrow payments, platform commissions.
-   **Integrations:** WhatsApp for vendor communication, AWS S3 for file storage.
-   **WhatsApp Admin:** A system for admins to view user messages, templates, and detailed logs.
-   **Compliance:** Meta (WhatsApp) compliant User Data Deletion policy.
-   **Drawings Protection:** An NDA mechanism before vendors can access drawings.

**User's preferred language**: English

**what currently exists?**
The OEMLinker application is a full-stack platform (React/FastAPI/MongoDB) with AWS S3 integration for file storage, JWT authentication, and a comprehensive Role-Based Access Control (RBAC) system.

The application's frontend is now highly dynamic and permission-aware. The sidebar navigation, dashboard Quick Action cards, admin panel tabs (Users, Vendors, RFQs), and even in-table action buttons (Edit/Delete) are all rendered conditionally based on the granular permissions assigned to the logged-in user's role. This allows for creating custom staff roles (e.g., Sales Manager, Support Agent) with very specific access rights. The backend API endpoints have been updated to enforce these permissions.
